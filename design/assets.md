# Assets

This describes how Tomori's environments load and draw models at runtime: content-addressed references to assets, where their bytes come from, how a file is read as untrusted input, the models and instances read from them, and drawing them skinned on the GPU. Assets are an extension point: an environment's own crate brings its assets and draws them with these, without changing Tomori.

## Requirement

**Loaded at runtime, not baked into code.** An environment's models, such as its animated creatures and props, are glTF 2.0 binary files (`.glb`), the shared format, read when the environment is drawn, never converted into code or tables at build time. Building Tomori needs no modelling tool. An environment that keeps a model's editable source, such as a `.blend`, keeps it beside the `.glb` with the script that exports one from the other, so that the `.glb` can be made again.

**Content-addressed.** An asset is named by an `AssetRef`: the environment it belongs to, at its protocol version, its name within the environment, which is also its path beneath a folder of assets (`ENVIRONMENT/NAME`), and the SHA-256 digest of its bytes, which is what it is. The reference is written in the environment's code beside what uses the asset, so that the asset changes only with the code that expects it: bytes that do not match the digest are never used, and an asset changed without its digest fails to load, saying so. An asset that changes what clients and the server agree on changes the environment's version, as anything else the environment's sides exchange does (see `environments.md`).

**Where the bytes come from.** A `Library` asks its sources in turn for an asset and uses the first bytes whose digest matches, logging any that do not; it reads each model once and shares it by digest with every instance and environment that asks. The program has one, `Library::shared()`. Today assets are bundled with the app: an environment's crate embeds its own with `include_bytes!` as an `Embedded` source, except on Android, where the APK carries them in its `assets` folder, at their paths, and the app adds the APK as a source; a `Directory` source reads a folder. A source that is missing an asset, or holds other bytes for it, leaves the environment drawn without it, saying why in the log, rather than failing.

**Untrusted input.** Every file is read as if hostile, whatever its source, since a later stage fetches assets over the network: `read` checks every size, count, index, offset, stride and range against the file and the `Limits` before reading or allocating anything from it, and refuses what it does not read rather than guessing. A broken, truncated, scrambled or oversized file is an `Error` saying what is wrong, never a panic or an unbounded allocation: by default a file is at most 16 MiB, its JSON 1 MiB, its textures at most 2048 texels on a side and 8 million together, decoded only once their headers have been checked, and its nodes, meshes, primitives, vertices, indices, materials, skins, joints, animations, channels and keyframes are each bounded, over the whole file, each part read within what the parts before it left, so that parts sharing one accessor cannot each claim the whole limit. It reads triangle meshes with positions, normals, texture coordinates, colours and up to eight joint influences, materials' base colours, textures, emissive light and alpha masks, PNG and JPEG images embedded in the file, skins, and animations of translations, rotations and scales, stepped or linear. It refuses external and data URIs, sparse accessors, cubic splines, morph targets and required extensions.

**Models and instances.** A `Model` is checked data, shared by all its instances: a node hierarchy with rest transforms, meshes, materials, decoded textures, skins and animations. Geometry built in code is a `Model` too, checked the same way (`Model::built`), so that a procedural model and one read from a `.glb` are drawn alike and either can replace the other. An `Instance` places a model in the scene with a transform, a `Pose` (each node's local transform, sampled from an animation, blended between two, or set by a controller) and nodes it shows or hides, such as a lantern's glass.

**Drawing.** With the `gpu` feature, on by default, a `Renderer` uploads a model once and draws a batch of its instances in an eye's pass: one draw for every instance of each primitive, each instance's joint matrices in a storage buffer, skinned in the vertex shader, or placed by its node's matrix if not skinned, lit by the scenery's ambient sky and ground light, the sun or moon, up to four lamps and haze, and cut off outside the sphere a scenery grows within. A mesh without normals is lit by its triangles' own. Textures are mipmapped in linear light, so distant models do not shimmer. The CPU skins a mesh the same way (`deformed`), for tests and for measuring how a model moves. An environment's server side, which draws nothing, depends on the crate without the feature, which leaves it with no GPU crate among its dependencies.

**Delivery from the server, next.** An environment's server side is to serve its assets by digest, and headsets to download and cache them, so that a headset can present an environment its build does not bundle (#194, with #75, #76 and #84). The reference is ready for it: a digest names the asset wherever it comes from, the environment and version say whose it is, and a new `Source` that fetches and caches by digest is added beside the bundled ones without changing anything that asks for assets. Fetched bytes are read as untrusted, as every file already is.

## Rationale

In November 2026 the maintainer decided that Tomori loads assets such as models at runtime rather than baking them into code: a model baked into one renderer's code at build time is out of reach of anything but that renderer, and the environment framework needs assets that environments bring and, later, that servers deliver. The `.glb` is the shared format because Blender exports it deterministically with the rig, animations, materials and textures, and the runtime reads it without Blender. A reader of its own, rather than a general glTF crate, keeps the checks on untrusted input explicit and complete, and reads only what Tomori draws. Content addressing makes an asset's identity independent of where it came from, which is what delivery from a server, caching and sharing between instances need. Embedding assets elsewhere and carrying them in the APK on Android keeps one copy in each build, and lets a downstream headset copy an environment's assets from its package into its own APK. The renderer draws every instance of a primitive in one draw, with joint matrices in a storage buffer, because environments are expected to grow to many animated instances; the maintainer asked for general layers, assets, model instances and drawing, which each environment's own crate builds on, rather than code for one environment's models.

## Scope

`crates/assets`: `reference.rs`, `library.rs`, `gltf.rs`, `model.rs`, `pose.rs`, `instance.rs` and, with `gpu`, `gpu.rs` and `model.wgsl`; and the APK's source in `crates/client-quest`'s `android.rs`, which the headset adds to the shared library as it starts.

## Validation

- Tests read a skinned glTF written by the tests, with every attribute, component type and interpolation the reader takes, a PNG and a JPEG texture, and check each value read; and refuse it broken in every way the reader checks, each with the kind of error it is: its header, its chunks, cut short, too large in bytes, JSON, counts or texture size (an image whose header claims 100,000 texels square is refused before it is decoded), indices and offsets out of range, strides that do not fit, counts that disagree, and what is not supported. Thousands of scrambled and truncated copies must neither panic nor allocate beyond the limits.
- Tests load an asset through a library from an embedded source and a folder, refusing bytes that do not match the digest, sharing the model read once, passing over sources without it, and never reading outside the folder.
- Tests skin a two-bone arm on the CPU at rest and bent, blend poses, and check that hidden nodes are not drawn.
- Rendering tests on lavapipe check that the GPU draws a skinned model where the CPU skins it, that every instance of a primitive is drawn in one draw with hidden nodes left out, that the reveal sphere cuts models off, and that a textured model read from a file is drawn; and every shader validates.
- CI lints the crate without `gpu` and fails if it then depends on `wgpu`, `naga`, `ash` or `tomori-render`.
- The first environment to bundle a model checks it against Blender's own deformation, at several frames of each animation, within a small tolerance.
